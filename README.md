# zipline

Новостной трекер по Deadlock. Первый модуль — **трекер разработчиков**: сообщения разработчиков
из официального Discord-сервера Deadlock в одной ленте, с поиском, фильтрами и кнопкой
«Текст для поста» для канала.

## Запуск

```bash
./run.sh
```

Сайт откроется на http://127.0.0.1:8000. Без настроек работает в демо-режиме (вымышленные авторы).

## Откуда берутся сообщения

Бота на официальный сервер Valve не добавить, поэтому есть два пути:

1. **Встроенный сборщик** (`backend/discord_collector.py`). Нужен токен Discord-аккаунта,
   который состоит на сервере Deadlock. Сборщик раз в `POLL_SECONDS` ищет по серверу сообщения
   от авторов из `backend/developers.json` — это охватывает все каналы и ветки за несколько запросов.
   ⚠️ Автоматизация обычного аккаунта нарушает правила Discord — используйте отдельный аккаунт,
   не основной.
2. **Внешний источник через `POST /api/ingest`** — любой мост или бот присылает сырые объекты
   сообщений Discord с заголовком `X-Ingest-Secret`. Формат описан в `backend/app.py`.

Настройки — в `.env` (образец: `.env.example`). После первого успешного получения
реальных сообщений демо-данные удаляются автоматически.

## Изменения в патчах

Страница `changes.html` («Изменения» в шапке) показывает, что поменялось в файлах игры от билда к билду:
модели, текстуры, материалы и эффекты по героям и зонам, новые строки локализации и значения
из игровых скриптов (было → стало).

Источник — открытый репозиторий SteamDB [GameTracking-Deadlock](https://github.com/SteamDatabase/GameTracking-Deadlock):
по коммиту на каждый билд Steam со списком файлов (с контрольными суммами), скриптами `.vdata` и английской локализацией.

```bash
python -m backend.patches            # скачать новые билды и записать сводки в data/patches/
python -m backend.patches --rebuild  # пересобрать последние PATCH_BUILDS (30) билдов заново
```

На GitHub это делает `.github/workflows/patches.yml` каждые 20 минут: коммитит новые сводки и перезапускает деплой.

### Модели и текстуры «до/после»

`backend/media.py` для последних 10 билдов достаёт из Steam изменённые модели и текстуры (только нужные
файлы из архивов игры, через [SteamFileDownloader](https://github.com/SteamTracking/SteamFileDownloader)),
конвертирует их [Source2Viewer-CLI](https://github.com/ValveResourceFormat/ValveResourceFormat) в GLB и WebP
и кладёт в GitHub-релиз `media-<билд>-<sha>`. Билды старше 10-го теряют медиа, их релизы удаляются;
общий объём ограничен `MEDIA_BUDGET_MB` (400). В git попадает только список файлов.

Нужны секреты репозитория `STEAM_USERNAME` и `STEAM_PASSWORD` — отдельный аккаунт с доступом к Deadlock
и **выключенным Steam Guard** (иначе вход с серверов GitHub требует код). Без секретов шаг пропускается.

## Герои

Страница `heroes.html` («Герои» в шапке) показывает всех играбельных героев карточками, как в игре. По клику
открывается окно с 3D-моделью из файлов игры: её можно крутить, выбирать анимацию, ставить на паузу и
выбирать кадр, а потом скачивать PNG на прозрачном фоне (×1/×2/×4). Кнопка «Скачать WebM» пишет
один цикл выбранной анимации (24 кадра/с) в WebM-видео с прозрачностью — размером с окно или
квадратом 500×500 / 100×100, куда герой вписывается целиком. Внутри VP9 плюс второй VP9-поток
с альфой, как это делает ffmpeg (тот же формат, что у видеостикеров Telegram). Safari прозрачность
в WebM не показывает.
Окно растягивается за угол и разворачивается на весь экран.

`backend/heroes.py` берёт список героев из `heroes.vdata` последнего билда, качает из Steam модель героя
со всем, что она использует, и конвертирует её Source2Viewer-CLI. Из анимаций остаются бег и ближний бой.
Материалы запекаются по логике шейдера игры: тинт по маске, контраст/насыщенность/яркость, цвет вершин
(в игре он в sRGB), карты нормалей; текстуры цвета — в исходном разрешении.
Модель (GLB, сжатая gltfpack) и пакет анимаций лежат в GitHub-релизе `heroes`; страница подгружает
каждую анимацию отдельно (HTTP range). Иконки и список — в `data/heroes/`.

```bash
python -m backend.heroes                  # сконвертировать новых и изменившихся героев
python -m backend.heroes --fetch DIR      # скачать модели из релиза (так делает деплой)
```

На GitHub это делает `.github/workflows/heroes.yml` раз в 6 часов (и вручную: можно указать героев в `only`).
Нужны те же секреты `STEAM_USERNAME` / `STEAM_PASSWORD`.

## Предметы и билды

Страница `items.html` («Предметы» в шапке) — магазин Deadlock как в игре: вкладки «Все / Оружие / Живучесть / Дух»,
предметы по тирам с ценой в душах (легендарные из «Уличной драки» — отдельным рядом), поиск по-русски и по-английски,
игровые фильтры («что даёт предмет», режимы «любой» и «все сразу»), сортировка по цене и названию. Наведение показывает
подсказку как в игре: характеристики, пассивка и активка с перезарядкой, рост от силы духа, из чего собирается.
По клику — карточка предмета: иконка в PNG 100×100, 300×300 или 500×500; внизу магазина — ZIP со всеми иконками
(или только с показанными) нужного размера.

Кнопка «Создать билд» превращает магазин в редактор, как в игре: клик по предмету кладёт его в выбранную категорию,
предметы перетаскиваются между категориями, к каждому можно оставить заметку; категории добавляются, переименовываются,
двигаются и получают описание. Есть выбор героя и порядок прокачки способностей (открытие и улучшения за 1, 2 и 5 очков).
Во вкладке «Билд» категории — блоки на сетке в 12 колонок, как во вкладке «Билд» в игре: блок переставляется за ⠿,
ширина и высота меняются за уголок (или стрелками), предметы во всех блоках одного размера и подгоняются под самый
тесный блок. Раскладка сохраняется в ссылке и JSON и так же выглядит на полноэкранной странице и на картинках.
Билды хранятся в браузере; «Ссылка» упаковывает билд в адрес страницы (deflate + base64). По ссылке билд открывается
на всю страницу — герой, категории с крупными предметами и заметками, прокачка; «Сохранить себе» копирует его в свои
билды и открывает редактор. Свой билд так же разворачивается кнопкой «На весь экран». Там же билд скачивается картинкой PNG 1080×1080 или
1920×1080: она рисуется на canvas заново под размер (герой, сумма, категории с предметами и заметками, прокачка),
поэтому кнопок и интерфейса сайта на ней нет. Есть экспорт и импорт JSON.

`backend/items.py` берёт предметы из `abilities.vdata` последнего билда (цены тиров — `generic_data.vdata`, английский
текст — локализация в репозитории SteamDB). Из Steam приходят иконки магазина (без потерь, в разрешении игры,
через Source2Viewer-CLI) и русская локализация; и то и другое качается заново, только когда файл в игре изменился
(контрольные суммы есть в `pak01_dir.txt` и манифесте депо). Результат — `data/items/index.json`, `data/items/icons/`
и `data/items/loc_ru.json` (нужные русские строки, чтобы балансный патч не требовал входа в Steam).

```bash
python -m backend.items             # обновить список, иконки и русский текст
python -m backend.items --offline   # только список, без Steam
```

На GitHub это делает `.github/workflows/items.yml` раз в час и после изменений `backend/items.py`.
Нужны те же секреты `STEAM_USERNAME` / `STEAM_PASSWORD`.

## Тир-лист

Страница `tierlist.html` («Тир-лист» в шапке) — свой тир-лист героев: строки S, A, B, C и D, под ними все герои
из `heroes/index.json` (по алфавиту, с поиском). Героя перетаскивают в строку, внутри строки — чтобы поменять порядок,
и обратно вниз — чтобы убрать; при перетаскивании к краю окна страница прокручивается сама. Перетаскивание сделано на
pointer-событиях, поэтому работает и мышью, и пальцем (на телефоне героя нужно чуть подержать, иначе палец листает
страницу). Без перетаскивания: нажать на героя, потом на строку, или клавиши S/A/B/C/D, Delete — обратно в список.
Тир-лист и его название хранятся в браузере. Кнопка «Скачать 1080×1080» рисует PNG на canvas заново: название, дата,
наш логотип и пять строк с портретами — размер портретов подбирается самый крупный, при котором влезают все строки.

## Reddit

Страница `reddit.html` («Reddit» в шапке) — «Пульс» r/DeadlockTheGame: свежие посты, которые набирают голоса
и комментарии быстрее своих ровесников, — наверху. Вкладки «Пульс», «Взлетают», «Новые», «Топ 24 ч»,
темы (новости, клипы, арт, обсуждения) и кнопка «Текст для поста».

**Алгоритм** (`backend/reddit.py`). Пост сравнивается только с ровесниками — постами возраста от 0,6 до 1,6 его
собственного, — поэтому 20-минутный пост с 30 голосами может обойти 10-часовой с тремя сотнями.
Сила — место среди ровесников по голосам и комментариям; разгон — рост силы за полчаса; новостям (патчи,
утечки, ссылки на сайты Valve) — надбавка; вес поста падает вдвое каждые 8 часов.

**Откуда данные.** Без ключа Reddit отвечает на JSON-запросы ошибкой 403, а ключи API с ноября 2025 года выдаёт
только после ручного одобрения. Поэтому по умолчанию используются публичные RSS-ленты: в них нет чисел, и Reddit
разрешает анонимно 1 запрос в минуту. Ленты чередуются: место поста в «топе часа», «горячем» и «топе дня» даёт
силу по голосам, а общая лента комментариев сабреддита — счёт комментариев. Если есть ключ API (приложение типа
script), положите `REDDIT_CLIENT_ID` и `REDDIT_CLIENT_SECRET` в секреты репозитория — сборщик сам перейдёт на
настоящие рейтинги и обновление раз в минуту.

Сборщик работает внутри `backend/live.py` (воркфлоу «Live collector»): лента для страницы — в Firebase
`/live/reddit` (страница перечитывает её раз в 90 секунд), полное состояние между запусками — в `/reddit/state`.

```bash
python -m backend.reddit          # локально: держать data/reddit.json свежим (страница берёт его через ./run.sh)
python -m backend.reddit --once   # один запрос и топ в консоль
```

## Список разработчиков

`backend/developers.json` — Discord ID и имена. Новые записи подхватываются при перезапуске;
имя и аватар обновляются из Discord автоматически.

## Структура

```
backend/   FastAPI + SQLite: API, сборщик Discord, демо-данные
frontend/  статичная страница (HTML/CSS/JS без сборки)
data/      база SQLite (создаётся при запуске)
```

## API

| Метод | Путь | Что отдаёт |
|---|---|---|
| GET | `/api/dev-messages?q=&authors=&channel=&before=&after=&limit=` | лента сообщений |
| GET | `/api/developers` | разработчики, число сообщений за 7 дней, последняя активность |
| GET | `/api/channels` | каналы с сообщениями |
| GET | `/api/dev-stats` | сводка: 24 ч, 7 дней, самый активный, график за 30 дней |
| GET | `/api/status` | состояние сборщика |
| POST | `/api/ingest` | приём сообщений от внешнего источника |
| GET | `/reddit.json` | посты Reddit для страницы (из `data/reddit.json`) |
